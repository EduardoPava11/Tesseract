## 3. Technical debt, ranked

### Blocking

1. **No device pass on anything.** D1–D4 above.
2. **CR1 has no user-visible cost.** "Keep all" was ruled with the storage line
   as part of the deal; the line does not exist. Until it does, the app grows
   unbounded silently. `CubeStore.totalBytes()` is ready; nothing shows it.
3. **The retention/edit loop is half a loop.** Cubes are written and
   `Reweave.reweave` reads them, but **nothing in the UI calls it** — there is
   no surface where a user makes a second GIF. The capability exists and is
   unreachable.

### Structural

4. **The additive ladder is law that the pipeline does not obey.**
   `AdditiveLadder.hs` AD1–AD12 green; measured conformance of a
   freely-assigned cube is **0.0 at rungs 16 and 32**. The S8 port is not
   started, so the decree ("all rungs require a meaningful additive") is
   currently true in the spec and false in the app.
5. **Only the identity edit executes.** Four of five Edit axes refuse:
   `eFig`/`eGnd` need the tree to record every level (shipped solver exposes
   depth 4 only) and `eGnd` awaits the λF/λB measurement; the octave weights
   need coarse and mid reads that do not exist.
6. **Occupancy is unchanged.** The ≤144/256 alphabet and the ≤17 σ ceiling are
   exactly as found. Everything this session added around occupancy was law,
   instrument and audit — no byte moved toward more colour.
7. **B3 vs B5 is unresolved.** They cannot both hold for a smoother. B5 was
   added and fails; the calibration that fixes it breaks B3 and FID. jepaH is
   off, so nothing depends on the answer today — but the next model does.

### Local

8. **FACE and LIVE now use different filters.** FACE box-averages in YCbCr
   (gamma) space, LIVE in linear light. FACE's error is far smaller than
   decimation was, but the twins disagree and the discrepancy is undeclared in
   any spec.
9. **`CubeStore.to8` duplicates `DyadPipeline.srgb8`.** Deliberate (the storage
   law should not drift with pipeline internals) and gated by a test, but it is
   still two copies of one rounding rule.
10. **CR3 is defined on the export path only.** The LIVE coarse reads pool raw
    floats before quantizing, so a `Live`-driven re-weave can differ by up to
    half a byte quantum. Documented in `CubeStore.swift`; not tested.
11. **The census trace rides every export** (`ADDITIVE CENSUS v1`) and nothing
    reads it back. Same for `RATE LEDGER v1`. Traces without readers rot.
12. **Docs outnumber device evidence 3:1.** `weave-architecture.md`,
    `occupancy-workflow.md`, `model-placement.md` are all from this session and
    all rest on synthetic measurement. `occupancy-workflow.md` already carries
    one CORRECTED banner where a claimed theorem was refuted.

## 4. Corrections made to this session's own claims

Recorded because the specs and docs still cite the session:

- **The 16→4→1 nesting was NOT a theorem.** `poolAt` is a stride-2 SUM (the
  phase moves the block origin, TL11), coarse reads re-assign rather than
  decimate, and the 2000/2000 matching evidence covers one 4:1 step at phase 0.
  Corrected in place in `occupancy-workflow.md` §1; superseded by the additive
  law, which authors balance per rung instead of pushing it through pooling.
- **The far law is dead code**, not a lever: `fars` is all-false at every
  production call site, so the alphabet ceiling is **≤144**, not 145.
- **The audit's "164 used" is a cube union**, not a per-frame count.
- **The NaN cascade's mechanism** is +inf crossover at π_B ≠ ½ and NaN only at
  π_B = ½ — both ending in a NaN pull. My first test asserted the wrong
  intermediate and failed; it now documents both routes.
- **"8-bit RGB is lossless because the source is 8-bit"** stopped being true
  when C3 made the in-memory value a continuous average. It survives for a
  different reason: `process` quantizes with `srgb8` as its first act, and
  `to8(byte/255) == byte`. The claim is now "the byte survives."
