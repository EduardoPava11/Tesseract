### refinable — QUALIFIED (axiomSafe=True)

**Original claim:** Equitz & Cover (1991) proved successive refinement (zero rate loss at each distortion level iff a Markov-chain condition holds; Gaussian/MSE and finite-alphabet/Hamming sources are successively refinable), and therefore Tesseract's multi-stage refinement ladder pays no rate-distortion penalty provided stages condition only on the previous stage and never revise coarse decisions.

**Corrected statement:** Equitz & Cover (IEEE Trans. IT 37(2):269-275, 1991) proved that an i.i.d. source is successively refinable (the two-stage code achieves R(D1) and R(D2) exactly, i.e., zero rate loss at each level) if and only if there EXISTS a joint conditional p(x_hat1, x_hat2 | x) whose marginals each achieve the rate-distortion function and which factors as the Markov chain X -> X_hat2 -> X_hat1 (coarse degraded from fine); sufficiency was earlier shown by Koshelev (1980). Gaussian sources under squared error and all finite-alphabet sources under Hamming distortion satisfy this condition; the result is an asymptotic block-coding theorem for the true source distribution under the stated distortion measure, with stage-wise R(D)-optimal codes. For Tesseract this theorem is a motivating prior for embedded/tree-structured code design, NOT a zero-penalty guarantee: the per-frame latent is a Gaussian FITTED to data the repo itself models as a two-phase mixture with bimodal hue statistics; the wire rate is fixed by decree (64 frames x 64x64 x 8-bit, per-frame 768-byte LCT) with ladders as telemetry only; the deployed objectives (OKLab distance, the PP1 phase energy F, the LZW-measured meter) are neither MSE nor Hamming; the greedy constrained-basis pair tree is not stage-wise R(D)-optimal (PC3 receives zero codewords); the ANE exchange loop deliberately revises prior index assignments by descent on F; and a single deterministic 64-cubed cube is outside the asymptotic i.i.d. regime. Any refinement-ladder rate cost must therefore be measured per capture by the RATE LEDGER and validated by device pass, per the repo's two-gate rule and no-naked-constants decree, never assumed zero by citation.

**Reason:** The literature attack UPHELD the theorem with accurate primary-source quotes (abstract iff statement, Section V.A Gaussian construction, Section V.B Hamming construction, Section IV counterexample under absolute error), adding only precision footnotes (existence-of-joint-conditional phrasing, X -> X_hat2 -> X_hat1 direction, asymptotic scope, Koshelev priority). ### ane — QUALIFIED (axiomSafe=True)

**Original claim:** On the Apple Neural Engine, each dispatch pays a fixed ~0.23 ms floor, so fixed-iteration multi-step computations should be UNROLLED AND FUSED into one dispatch; separate per-step dispatches are only worth it when the step count must adapt at runtime and a skipped step saves more than the dispatch floor.

**Corrected statement:** On the Apple Neural Engine, every dispatch pays a fixed floor that pipelining cannot hide (the driver keeps one firmware command in flight): measured ~0.23 ms on the M1 anchor, fitted ~0.11 ms on M5, unmeasured on A-series iPhones — pin the floor per target device before using it as a decision threshold. For fixed-iteration computations, unroll and fuse into one dispatch so the floor is paid once per sweep (the engine's widest efficiency margin, 47.8–49x vs GPU on a fused 32-step stencil), subject to real ceilings: unrolled-chain compile time bounds in-graph unrolling (~n=20–32), and a fused graph can exceed op limits and fail ANECCompile outright, dropping off the engine entirely. Data-dependent trip counts cannot run on the engine at all: convergence-gated loops must fuse at a compile-time worst-case sweep count. Per-step (per-sweep) dispatch is the canonical pattern for streaming workloads with fresh operands per iteration (per frame/token/request, with resident state across dispatches) and for host-side budget-driven stopping between dispatches — not for on-engine early exit, which does not exist; where truly runtime-adaptive iteration counts are needed, a non-ANE port (e.g. a Metal kernel with K as a runtime loop bound) is the correct placement. Application note for Tesseract: the fused ANE loop is the algebraic Gauss-Seidel exchange solver (ANELoopModel = 256 fused stages, ANELoopK1 = 64 fused stages = one sweep per dispatch), not JEPA — the learned operator is an unbuilt future slot — and the fuse-vs-stream-vs-Metal choice per cadence tier stays open until the owed A19 Pro bench pins the device floor with provenance.

**Reason:** The claim's core is primary-source-backed and survives hostile reading: the dispatch floor is real, submissions serialize so the floor cannot be hidden, and Bryngelson (arXiv:2606.22283) explicitly prescribes fusing fixed-trip-count loops into one graph with measured 47.8–49x margins. The application attack is fully credited on verified code facts: no JEPA stages exist (algebraic exchange solver; learned operator unbuilt), stage counts are 256/64 not 64/1 (verified: stages = [1: 64, 4: 256] in ANELoopBenchTests.swift), 'adaptive early exit' contradicts the design (no convergence test; K1 = streaming polyphase cadence; the adaptive-K placement is the omitted Metal SIMT port), and using 0.23 ms as a threshold violates the no-naked-constants decree with the device bench still owed.
